# Phase 4 - Complete international pricing coverage + Default Store Image fallback

Baseline: backend `staging` 4aaec4c, Flutter `staging` b779af8. Nothing committed, pushed, merged or deployed. Production untouched. Signing keys untouched.

## Gaps from Phase 3 and what was done
| # | Gap | Fix |
|---|-----|-----|

## Default Store Image
* **Where the mapping was wrong.** Flutter (0446265) showed the Default Store Image for EVERY empty Home, so a place outside the service area also got the "no stores" image, and the No Service Area image was only used when no store image existed. Backend: `/default-images` returned only the first store image (`store`), so several configured images never rotated.
* **Backend** (`routers/public.py`): `/default-images` now also returns `store_images` (all usable images for the country, same country mapping and "All countries" rule; `store` is unchanged for older apps). New `GET /city-status?city=&country=` -> `{supported}` using the City Master (active cities of the country; English name, slug or any translation; whole-word match for GPS style names; the active stores' cities when there is no City Master).
* **Flutter** (`lib/main.dart`, `default_store_image.dart`, `api_service.dart`): when a successful load returns zero stores, Home asks `/city-status`. In the service area -> Default Store Image (random one when several, re-picked each time); outside the service area, or not known (request failed) -> the existing No Service Area image / message, exactly as before. Error / offline / timeout states are untouched.

## Things to know
* `lib/l10n/gen/*.dart` were edited by hand in the exact shape `flutter gen-l10n` produces (no Flutter SDK here). Please run `flutter gen-l10n` once locally and confirm there is no diff; `tools/gen_remote_l10n.py` was re-run (`--check` passes) and `tools/check_l10n.py` passes.
* A backend that is older than this release has no `/city-status`: the app then treats the city as "not known" and shows the No Service Area image (the pre-0446265 behaviour).
* Still India-only by design: the reward conversion rate / minimum withdrawal (`pricing.conversion_rate`), `GET/PUT /admin/banner-pricing` (legacy India editor), the admin dashboard's own rupee labels.
* `/discount/validate` (public, unauthenticated preview) is unchanged; the checkout and the merchant preview enforce the currency rule.
